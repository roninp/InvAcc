# InvAcc

Приложение для мониторинга и ребалансировки инвестиционного портфеля
(Next.js 16, React 19, TypeScript, Tailwind CSS). Котировки берутся из
**Finam Trade API** (тариф «Про») с fallback на **MOEX ISS**.

## Требования

| Компонент | Версия | Зачем |
|-----------|--------|-------|
| [Node.js](https://nodejs.org/) | LTS (24.x и выше) | Среда выполнения |
| [pnpm](https://pnpm.io/installation) | 9.x и выше | Пакетный менеджер проекта |

Как проверить установку:

```bash
node --version
pnpm --version
```

Если `pnpm` не установлен:

```bash
npm install -g pnpm
```

## 🚀 Быстрый запуск (одной кнопкой)

1. Двойной клик по файлу **`start.bat`** в корне проекта.
2. Скрипт сам:
   - проверит Node.js и pnpm;
   - установит зависимости (`pnpm install`), если `node_modules` ещё нет;
   - создаст `.env.local` из `.env.example`, если он отсутствует;
   - запустит dev-сервер и через ~8 секунд откроет браузер на
     `http://localhost:3000`.
3. Чтобы остановить — нажмите `Ctrl+C` в открывшемся окне.

## 🖥️ Ручной запуск

```bash
# 1. Установка зависимостей (первый раз)
pnpm install

# 2. Настройка окружения (первый раз)
copy .env.example .env.local
#   Затем отредактируйте .env.local — заполните FINAM_API_SECRET.

# 3. Запуск дев-сервера
pnpm run dev
```

Откройте в браузере: <http://localhost:3000>

## 🔐 Переменные окружения (`.env.local`)

| Переменная            | Обязательная | Описание |
|-----------------------|:---:|----------|
| `FINAM_API_SECRET`    | ✅  | Секретный токен Finam Trade API. Получается на <https://api.finam.ru/tokens/>. Без него не работают мгновенные котировки. |
| `FINAM_ACCOUNT_ID`    | нет | Номер брокерского счёта (без префикса «КлФ», только цифры). Позволяет брать лот напрямую из Finam API. Если не задан — лот берётся из fallback (MOEX ISS). |
| `FINAM_TLS_INSECURE`  | нет | `1` — отключить проверку TLS-сертификата (нужно для корпоративного SSL-перехвата). **Только для локальной разработки.** |
| `NEXT_PUBLIC_SUPABASE_URL`     | ✅  | URL Supabase-проекта (Dashboard → Project Settings → API). |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY`| ✅  | Публикуемый (publishable) ключ Supabase. Публичный ключ — безопасен для браузера. |

## 🔑 Авторизация (Supabase Auth)

Регистрация и вход выполняются через Supabase Auth (email + пароль). При
регистрации на указанную почту приходит письмо с ссылкой подтверждения
(обязательное подтверждение email). Тариф пользователя хранится в таблице
`public.profiles` и **назначается вручную** — на сайте изменить его нельзя.

Как настроить отправку писем (SMTP) в Supabase:

1. Откройте **Dashboard → Project Settings → Auth → SMTP**.
2. Включите **Enable Custom SMTP** и заполните данные своего почтового сервера
   (например, Yandex: Host `smtp.yandex.ru`, Port `465`, SSL `On`, User и
   Password — от почтового ящика, от которого приложение шлёт письма,
   Sender — тот же адрес). Без SMTP Supabase использует встроенный mailer,
   который для не-проверенных доменов письма не доставляет.
3. В **Auth → URL Configuration** задайте `Site URL = http://localhost:3000`
   (в продакшене — домен сайта) и добавьте в `Redirect URLs`
   `http://localhost:3000/**`.

**Смена тарифа пользователя (вручную через БД):**

```sql
-- Dashboard → SQL Editor
update public.profiles
set tier = 'pro'   -- 'free' | 'basic' | 'pro'
where email = 'user@example.com';
```

При входе приложение прочитает новый тариф из БД автоматически.

## 🧷 Контроль соответствия портфеля тарифу

Если сохранённый портфель (localStorage) превышает лимиты текущего тарифа —
больше активов, чем разрешает «Бесплатный» (2) или «Базовый» (100), либо
используются группы активов (фича «Про») — приложение:

1. паркует портфель в резервную копию (ключ `portfolioRebalancerLockedData`);
2. обнуляет рабочий стол — при этом приложение остаётся полностью рабочим
   в рамках текущего тарифа (например, на «Бесплатном» можно собрать новый
   портфель до 2 активов);
3. показывает баннер **«Ваш портфель соответствует тарифу „…“. Будет доступен
   после оплаты подписки»** с кнопкой-заглушкой «Оплатить подписку» (система
   оплаты появится позже; сейчас кнопка ведёт на главную страницу, где
   размещено описание тарифов).

После повышения тарифа (смена `tier` в БД) «прошлый портфель» автоматически
восстанавливается при перезагрузке страницы, повторном входе или на
auth-событиях `SIGNED_IN` / `USER_UPDATED` — и затирает текущий портфель.
Пока тариф не повышен, резервная копия остаётся в неприкосновенности.

Ключи localStorage:

| Ключ | Что хранит |
|------|------------|
| `portfolioRebalancerMeta` | Индекс коллекции портфелей: id, имена, активный портфель |
| `portfolioRebalancerData` | Исторический ключ портфеля №1 («Основной») |
| `portfolioRebalancerData:<id>` | Данные портфеля №2+ |
| `portfolioRebalancerLockedData` | Резервная копия содержимого портфеля, заблокированного тарифом (удаляется автоматически после восстановления) |
| `portfolioRebalancerLockedCollection` | Припаркованные портфели, превысившие лимит тарифа (автоматически возвращаются после повышения тарифа) |

## 🗂️ Портфели на тарифе «Про»

Приложение поддерживает несколько портфелей:

| Тариф | Портфелей | Активы |
|-------|-----------|--------|
| Бесплатный | 1 | до 2 |
| Базовый | 1 | до 100 |
| Про | до 5 | до 100 + группы |

Переключение между портфелями — селектор в шапке рядом с тарифом.
Создание, переименование и удаление — на странице «Портфель» (удалить
последний портфель нельзя).

Если у пользователя оказывается больше портфелей, чем разрешает текущий
тариф (например, тариф понизили с «Про»), лишние портфели автоматически
паркуются в `portfolioRebalancerLockedCollection` и исчезают из селектора;
рабочим остаётся активный портфель. При повышении тарифа до «Про» они
автоматически возвращаются вместе со всеми данными. Резервная коллекция
хранится до момента восстановления и не удаляется при сбросе активного
портфеля.

## 📈 Фондовый сектор vs срочный рынок

Система производит расчёт **только для фондового сектора Московской биржи**:
акции, облигации и ETF (иностранные бумаги через депозитарные расписки).
Инструменты **срочного отдела** — фьючерсы, опционы и прочие производные
(движок `futures` на MOEX ISS, рынки `forts`/`options`) — использовать нельзя:

1. При вводе тикера (с задержкой ~0,6 с после остановки набора) актив
   проверяется через MOEX ISS на принадлежность к срочному рынку.
2. Такой актив **подсвечивается** в таблице (бейдж «Срочный рынок»), цена для
   него не загружается, а инструмент не участвует в расчёте.
3. При обновлении цен показывается информационное сообщение, что система
   производит расчёт только для фондового сектора Московской биржи; связанные
   ошибки загрузки для таких тикеров скрываются.

Проверка выполняется на каждом изменении тикера, при восстановлении портфеля
из localStorage, импорте из файла и переключении портфеля. Результат
кэшируется на сессию (сектор инструмента не меняется на лету), но **не
сохраняется** в данных портфеля.

## 🧪 Тестирование

Проект использует [Vitest](https://vitest.dev) для unit-тестов слоя логики
(хранилище `PortfolioStorage`, валидатор email, сервис аутентификации).
Тесты не требуют браузера: `localStorage` эмулируется, клиент Supabase
подменяется моком.

Запуск всех тестов:

```bash
pnpm test        # однократный прогон (vitest run)
```

Файлы тестов:
- `lib/__tests__/storage.test.ts` — слой персистентности, включая регрессию
  на сценарий «портфель не теряется при перезапуске» и резервную копию при
  несоответствии тарифу (`saveLocked`/`loadLocked`/`clearLocked`).
- `lib/__tests__/portfolio-tier.test.ts` — логика соответствия портфеля тарифу
  (требуемый тариф, ранги, решение guard-эффекта: park / reset-excess / restore).
- `lib/__tests__/email-validator.test.ts` — валидация email-адресов.
- `lib/__tests__/auth-service.test.ts` — Result-контракты `AuthService`
  (регистрация, вход, выход, чтение тарифа из БД).
- `lib/__tests__/derivative-service.test.ts` — детекция инструментов срочного
  рынка Мосбиржи (фьючерсы/опционы) через MOEX ISS (в т.ч. квир «HTTP 200
  с пустым `securities.data`» для несуществующих secid) и текст сообщения про
  фондовый сектор.

## 🧹 Устранение проблем

**«Node.js / pnpm не найден»** при запуске `start.bat`
: Установите Node.js (перезапустите терминал после установки) и
  `npm install -g pnpm`.

**Ошибка `Finam lot params failed: 400 "Invalid arguments: account_id"`**
: В `.env.local` задан некорректный или пустой `FINAM_ACCOUNT_ID`. Проверьте
  номер счёта в личном кабинете Финама (формат «КлФ-<номер>», указывать без
  префикса) или оставьте поле пустым, чтобы использовался fallback MOEX ISS.

**Предупреждение про `pnpm.overrides` при запуске**
: В `package.json` есть ключ `pnpm.overrides`, который новые версии pnpm
  игнорируют. Это безвредно и не мешает запуску.

**Порт 3000 уже занят**
: Запустите с другим портом: `pnpm run dev -- -p 3001` и откройте
  `http://localhost:3001`.

**Котировки не обновляются**
: Проверьте, что `FINAM_API_SECRET` заполнен валидным токеном Финама, а ключ
  и сеть разрешают доступ к `api.finam.ru`.
